## 本轮修正的问题

- **qa 黑盒回归曾整体失效**：`qa/online-smoke.mjs` 编写于“3 秒同步倒计时 + 断线保护暂停”机制之前，开局立即操作会被 `COUNTDOWN`/`PAUSED` 拒绝，认输后无法进入结算，表现为“结算同步超时”。已在该脚本加入“倒计时结束且未暂停”“恢复后解除暂停与倒计时”两个等待条件。旧记录中“121 项通过、20/20 黑盒结算”为倒计时机制前的结果，**以本节表格为准**。
- **再来一局并发**：双方几乎同时点击“再来一局”时第二个请求曾被拒绝；服务端对已进入等待状态的重复请求返回成功，巡回赛比分只推进一次（`server/rooms.js`，回归测试在 `tests/rooms.test.js`）。
- **运行状态文件**：`runtime/state.json` 曾残留已退出进程的 PID，导致停止工具无法命中；已校正为当前服务进程。

## 部署说明与验证边界

当前 GitHub 授权没有 `workflow` 范围，因此采用已验证可用的发布分支方式。`scripts/publish.ps1` 提供测试、构建与分支发布；完整 Actions 模板保存于 `docs/pages-workflow-template.yml`，未声称该模板当前已经在运行。

公网对战服务在本机运行，需保持开机联网。当前使用临时公网隧道，启动器会同步变更后的地址；没有固定域名或持续可用性保证。要长期固定地址，可另行接入自有域名的命名隧道或独立云主机。

浏览器验证由同一电脑上的两个独立浏览器上下文完成，其中一个使用手机尺寸和触摸能力；没有把它表述为真实异地手机/蜂窝网络测试。后端重启会清空正在进行的内存房间，SQLite 保留已经结束的对战。没有对所有操作系统、浏览器引擎和高延迟条件作兼容性或公平性保证；反应力游戏会提示网络延迟影响。
