## 两个人怎么玩

1. 房主在自己的电脑上双击 `启动面对面的小游戏.cmd`，等待本机服务和公网入口就绪。
2. 打开上述在线页面，输入昵称、选择游戏、创建房间。
3. 复制房间里的邀请链接发给搭档，或告诉对方六位房间码；邀请链接自动携带服务器地址。
4. 两人都点击准备，经过 3 秒同步倒计时后开局。每款游戏内可展开玩法说明；结算后可再来一局或返回房间换游戏。
5. 房主选择 3/5 场巡回赛后，每场结算点击下一场，系统随机选择下一款，双方重新准备。

第一次打开时浏览器可能需要几秒连接服务器。遇到服务器离线，打开右上角连接设置，重新获取公开地址，或粘贴房主提供的 HTTPS 地址。

新版本机地址为 `http://127.0.0.1:4390`。大厅提供“单人挑战 AI”，32 款均有专用策略，默认大师，也可选择高手或休闲、我先手或 AI 先手。今日同种子挑战使用日期与游戏生成固定开局，可反复练习。单人模式无需连接对战服务，进度与 AI 已观察到的记忆自动保存在浏览器，重新打开后点击“继续单人存档”。首次载入页面与资源需要网络。

“同设备轮流试玩”继续保留，可手动切换玩家熟悉双方玩法。单人和试玩切到后台都会暂停计时，单人另提供手动暂停 / 保存。结算记录胜场、局数和最高分。

## 本机与公网入口

GitHub Pages 只托管前端。真实房间、随机数、规则判定、隐藏信息、计时、碰撞和胜负在本机 Node.js 服务器计算。**客户端只发送操作，从不上传分数、生命或胜者。**

- **远程对战要求房主电脑开机、联网，且 Node.js 服务与隧道进程保持运行。** 关闭电脑或停止服务后，网页仍可打开，在线对战不可用。
- 临时 Cloudflare Tunnel 没有固定域名或持续可用性保证，每次新建隧道地址可能变化。长期使用可将同一后端连接到自有固定域名 / 命名隧道。
- 启动工具会尝试把新的公开入口写入仓库的 `runtime-endpoint.json`。页面从该文件获取当前地址，避免每次隧道重启都重新构建前端。若本机 GitHub CLI 未登录或没有权限，仍可复制启动工具输出的带 `server` 参数链接发给搭档，不影响本地服务启动。

浏览器切到后台、关闭页面或短暂断线时，席位保护 **3 分钟**；进行中的对局冻结，双方回来后经过 2 秒倒计时继续。身份保存在浏览器本地，重新打开页面会尝试恢复原座位。超过 3 分钟未返回才按缺席结算；等待房间不会因切走两分钟而立即关闭。

默认使用 Socket.IO（HTTP 轮询建立连接后升级 WebSocket）；失败后自动切换**独立的 HTTPS 长轮询 API**。右上角连接设置也能主动选“HTTPS 兼容”。它们共享同一房间、序号和权威规则，可以在同一局中切换。后台系统可能挂起网络，恢复依赖保留身份、冻结进度与重同步，不能保证后台套接字一直存活。

SQLite 每 2 秒及关键房间事件保存私有检查点。服务重启后可恢复原房间、棋盘、令牌与序号，并重新给予返回保护期；意外断电最多可能丢失最近约 2 秒的过程。数据库和令牌仅保存在 D 盘，不提交到 GitHub。详情见 [联机稳定性与 AI 说明](docs/联机稳定性与AI说明.md)。

## D 盘运行

本机项目：`D:/codexAI/duizuo`。Node 使用 `D:/codexAI/.toolchains/emsdk/node/24.19.0_64bit/node.exe`，所有项目依赖、临时文件、数据库、下载、浏览器资料和日志都保留在 D:。

```powershell
& 'D:\codexAI\.toolchains\powershell\pwsh.exe' -NoProfile -File 'D:\codexAI\duizuo\scripts\start.ps1'
```

停止：双击 `停止面对面的小游戏.cmd`。脚本仅停止记录在本项目状态文件内、且命令行匹配本项目的 Node / 隧道进程。

`runtime/` 包含私有运行资料，不纳入 Git：

- `runtime/bin/cloudflared.exe`：公网隧道执行程序
- `runtime/logs/`：服务与隧道日志
- `runtime/data/duizuo.sqlite`：对战记录及进行中房间的私有检查点
- `runtime/state.json`：本项目启动的进程与当前地址
- `runtime/temp/`：临时文件

## 发布

页面由 GitHub Pages 托管，联机服务运行在本机。

```powershell
# 测试 → 构建 → 推送 gh-pages 分支 → 触发 Pages 重建（线上约 1 分钟内更新）
& 'D:\codexAI\.toolchains\powershell\pwsh.exe' -NoProfile -File 'D:\codexAI\duizuo\scripts\publish.ps1'
```

只推 `gh-pages` 分支不会立刻刷新线上站点，发布脚本已自动补上 `POST /pages/builds` 触发重建。

**关于 GitHub Actions 自动发布**：完整的 Actions 工作流已写好（`docs/pages-workflow-template.yml`，内容与本地 `.github/workflows/pages.yml` 一致），但当前 GitHub 授权缺少 `workflow` 作用域，GitHub 会拒绝创建或更新 `.github/workflows/` 下的文件。**经项目负责人决定，本次不启用自动发布**，改用上面的发布脚本手动发布；若日后想启用，补上作用域后执行：

```bash
gh auth refresh -h github.com -s workflow
git add -f .github/workflows/pages.yml && git commit -m "ci: enable Pages auto publish" && git push
```

然后把 Pages 的 Source 从 `gh-pages` 分支切到 **GitHub Actions** 即可。

页面只托管前端，联机服务始终运行在本机。

> **网络受限时怎么推送**：本机到 `api.github.com` 的链路有时会经代理抖动（TLS EOF / 连接重置），此时 `git push` 会失败。仓库自带一条 API 通道作为替代：
>
> ```bash
> node qa\api-commit-files.mjs main <要改的文件...>   # 只提交指定文件
> node qa\api-push.mjs <本地提交> main               # 推送整条本地提交
> node qa\api-publish.mjs                            # 直接发布站点到 gh-pages 并触发 Pages 重建
> ```
>
> `gh` 直连时需绕过代理：`$env:NO_PROXY='api.github.com,github.com,raw.githubusercontent.com'`。

公开仓库不包含访问令牌、隧道凭据、数据库或用户浏览器资料。
