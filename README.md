# DUO PLAY · 双人游乐场

20 款小游戏、一个双人房间。支持手机/电脑、六位房间码、链接邀请、双人准备、在线对战、结算、重连、3/5 场随机巡回赛、音效开关与本机战绩。

在线页面：**https://yjj0339.github.io/duo-play/**

## 20 款游戏

五子棋、隐藏海战、点格夺地、翻牌记忆、迷你冰球、口袋坦克、泡泡炸弹人、贪吃蛇竞技场、方块攻防战、弹弓城堡、迷宫夺旗、知识擂台、2048 对决、数独竞速、黑白棋、石头剪刀布、反应力对决、扫雷竞速、打字竞速、节奏记忆。

五子棋、2048、数独参考已有作品的规则和交互方向重新整合为双人模式；旧项目未被覆盖，也不包含旧项目的第三方 AI 引擎或用户存档。

## 两个人怎么玩

1. 房主在自己的电脑上双击 `启动双人游乐场.cmd`，等待本机服务和公网入口就绪。
2. 打开上述在线页面，输入昵称、选择游戏、创建房间。
3. 复制房间里的邀请链接发给搭档，或告诉对方六位房间码；邀请链接自动携带服务器地址。
4. 两人都点击准备，经过 3 秒同步倒计时后开局。在每款游戏里可以展开玩法说明，也支持结算后再来一局或返回房间换游戏。
5. 房主选择 3/5 场巡回赛后，每场结算点击下一场，系统随机选择下一款，双方重新准备。

第一次打开时浏览器可能需要几秒连接到服务器。遇到服务器离线，打开右上角连接设置，重新获取公开地址，或粘贴房主提供的 HTTPS 地址。

本机 `http://127.0.0.1:4387` 也可直接打开游戏。大厅提供明确标注的“同设备轮流试玩”：切换操控玩家查看双方玩法，它不包含 AI 对手，也不是两套同时响应的键盘。

## 本机与公网入口

GitHub Pages 只托管前端。真实房间、随机数、规则判定、隐藏信息、计时、碰撞和胜负在本机 Node.js 服务器计算。客户端只发送操作。

**远程对战要求房主电脑开机、联网，且 Node.js 和隧道进程保持运行。** 关闭电脑或停止服务后，网页仍可打开，在线对战不可用。临时 Cloudflare Tunnel 没有固定域名或持续可用性保证；每次新建隧道地址可能变化。长期使用可将同一个后端连接到自有固定域名/命名隧道。

启动工具会尝试把新的公开入口写入仓库的 `runtime-endpoint.json`。页面从该文件获取当前地址，避免每次隧道重启都重新构建前端。如果本机 GitHub CLI 未登录或没有权限，仍可以复制启动工具输出的带 `server` 参数链接发给搭档，不影响本地服务启动。

浏览器会自动重连；刷新当前标签页也会保留这个标签页的身份。对局中断线超过 60 秒判负。服务器重启会清空进行中的内存房间，**不恢复重启前正在进行的对局**。SQLite 只保存已经结束的比赛。

## D 盘运行

本机项目：`D:/codexAI/duo-play`。Node 使用 `D:/codexAI/.toolchains/emsdk/node/24.19.0_64bit/node.exe`，所有项目依赖、临时文件、数据库、下载、浏览器资料和日志都保留在 D:。

```powershell
& 'D:\codexAI\.toolchains\powershell\pwsh.exe' -NoProfile -File 'D:\codexAI\duo-play\scripts\start.ps1'
```

停止：双击 `停止双人游乐场.cmd`。脚本仅停止记录在本项目状态文件内、且命令行匹配本项目的 Node/隧道进程。

`runtime/` 包含私有运行资料，不纳入 Git：

- `runtime/bin/cloudflared.exe`：公网隧道执行程序。
- `runtime/logs/`：服务与隧道日志。
- `runtime/data/duo-play.sqlite`：已结束的对战记录。
- `runtime/state.json`：本项目启动的进程与当前地址。
- `runtime/temp/`：临时文件。

## 开发与验证

安装依赖前设置 D: Node PATH、TEMP、TMP 和 npm 缓存，然后执行 `npm ci`。`npm test` 包含三组游戏规则测试、房间协议测试，以及真实 Socket.IO 客户端逐款开局/操作/结算/再来一局的网络测试。`npm run build` 生成 `dist/`。

`scripts/inspect-ui.mjs` 用现有 D: Playwright/Chromium 检查 20 款游戏在 320/390px 的渲染和双浏览器联机。`scripts/verify-online.mjs` 检查线上发布后的实际双浏览器操作。`scripts/engine-playthrough.mjs` 使用只读取玩家视图的测试控制器，模拟全部 20 款从开局到正常或超时结算。浏览器验证依赖本机 D: 测试工具；Actions 模板只运行纯 Node 规则与网络测试。

验证结果见 `docs/验收记录.md`。真实异地手机/蜂窝网络验证需要实际第二设备，不能由同一电脑的两个浏览器上下文替代。

## 源码结构

`games/*-engines.js` 为纯规则；`games/*-views.js` 为保持 DOM/输入焦点的渲染器；`server/rooms.js` 管理房间与身份；`server/index.js` 提供静态页面、健康检查、Socket.IO 与 SQLite；`client/main.js` 管理大厅、联机、结果和试玩。

完整制作提示词见 `docs/制作提示词.md`，引擎接口见 `docs/CONTRACT.md`。

## 发布

当前使用 `gh-pages` 发布分支，执行 `scripts/publish.ps1` 会测试、构建并推送页面。现有 GitHub 授权缺少 `workflow` 范围，因此 Actions 工作流保留在 `docs/pages-workflow-template.yml`；如以后自行启用，可将它放入 `.github/workflows/` 并切换 Pages 发布方式。只更新主分支的公网入口文件不需要重建整站。公开仓库不包含访问令牌、隧道凭据、数据库或用户浏览器资料。
