# 3.3.1 · 横过来，认真打一场

这次重做羽毛球、乒乓球、台球的模型与场内呈现，合集仍为 32 款。其余 29 款继续使用已有渲染器；没有宣称全合集都变成了立体游戏。

## 操作与模型

- 三款球场使用正交摄像机呈现 2.5D 场景。人物分节跑跳、手臂双骨 IK、带拍线的球拍、羽球羽片、球网、台面支架、脚轮、木质球台与袋口均为本地程序模型。
- 羽毛球默认只有左右移动、击球、起跳四个主按钮；击球根据权威触球条件选择高远或扣杀。进阶面板可手动指定高远、吊球、扣杀及落点；双击方向冲刺，保留键盘快捷键。
- 手机竖屏时先暂停并提示横置。横屏保留返回、菜单、比分和双拇指操作区，支持安全边距。全屏与方向锁仅在浏览器支持、且用户点击时申请；不支持时提供手动转屏提示。
- 进阶面板和转屏使用独立暂停持有记录。联机向服务端发送暂离状态，两人一起暂停，回来后沿用已有倒计时；不修改判分规则或比赛进度。
- 世界坐标转换同时用于球、落点与点击反投影。修正球号不能按球数组下标取模型的问题；入袋动画结束后球保持隐藏，恢复存档不会重播旧入袋。

## 性能与恢复

- Three.js 0.186.1 按需加载，压缩后运动场景模块约 156 KB；无外部素材请求。MIT 许可随站点发布。
- 静态模型按材质合并；静态材质与几何体复用。运动绘制上限 60 Hz，物理步进和服务器判定独立。
- 手机默认流畅模式：分辨率系数最高 1.25，关闭实时阴影，保留接触投影和模型光照。精细模式最高 2 倍分辨率，宽度上限 1600。
- 退出后释放 RAF、ResizeObserver、事件监听器、模型、材质、纹理和 WebGL 上下文。上下文丢失有可见反馈，可恢复或在保留对局的情况下切换轻量球场。
- 此次沿用原本的 Socket.IO / HTTPS 双通道、3 分钟保护与持久化；临时公网隧道仍依赖本机和隧道进程持续运行。

## 3.3.1 手感与轨迹修订

- 羽毛球和乒乓球允许最多 140 ms 的提前击球输入。只在同一回合进入合法触球范围时提交一次普通击球请求，服务端继续验证；不扩大碰撞范围，不允许提前截击。暂停、失焦、换分、结束或过期都会清除。
- 自动高低球按实际触球时的高度选择；手机起跳和乒乓回击在按下时响应，无需等手指松开。
- 两帧间的球路经过已确认的触拍点、弹台点；换分、长时间断帧、恢复旧状态时直接对齐新状态，避免跨场拉线。台球自由球放置直接落到选定位置。
- 新增 11 项输入与轨迹测试；全套规则/保存/联网测试累计 311 项通过。浏览器验证提前触屏接球只出一拍、暂停清除缓存及按下起跳，运动玩法回归 10 项通过。
- `artifacts/dimension-v8/rally-final/profile.json`：修订后的六组 8 秒采样仍约 59–60 FPS，回调 P95 约 0.7–1.5 ms；只代表本机 Chromium 测试。
