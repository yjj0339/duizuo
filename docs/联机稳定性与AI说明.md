# DUO PLAY 2.0：恢复对局与单人 AI

## 本次修复

旧版断线 60 秒判负、断线时模拟继续、标签页身份不持久，都会导致切出分享后无法接着玩。新版在 visibilitychange / pagehide 时发送离开前台通知，服务器也检测断线；以第一次暂离时刻计算 180 秒保护，重复通知不会延长。双方回到前台后冻结解除前有 2 秒倒计时。游戏规则使用虚拟时钟，暂停不改变引擎内部状态，各游戏公开时间戳转换回显示时钟，避免恢复时立即超时。

身份令牌保存在浏览器本地；恢复后沿用原座位和操作序号。网络超时不会删除身份。同一身份在另一个页面恢复时，旧页面停止自动抢回连接。邀请链接只带服务器地址和房间码，不携带身份令牌。活跃房间检查点每 2 秒和关键事件写入 D 盘 SQLite；重启后以暂停状态恢复，双方重新连接。

## 两种联机通道

| 通道 | 适用情况 | 行为 |
| --- | --- | --- |
| Socket.IO | 常规低延迟实时对战 | 从 HTTP 轮询连接、尝试升级 WebSocket，启用恢复窗口并重新获取个性化快照 |
| 独立 HTTPS 长轮询 | WebSocket 或 Socket.IO 请求受阻、移动网络不稳定 | 原生 fetch POST 操作、GET 等待快照；Bearer 身份与会话绑定；与实时玩家进入同一房间 |

自动模式在连接失败后启用第二通道，设置也可手动选兼容连接。HTTPS 通道是 `/api/session`、`/api/command`、`/api/snapshot`、`/api/presence`，不依赖 Socket.IO 的网络协议。空闲时长轮询最多等待 20 秒，活跃局面约 10Hz 更新；实时动作游戏中兼容通道可能增加延迟。

研究过 WebRTC / PeerJS 直连，但 NAT 下常需 TURN 中继，手机挂起页面后仍会失去连接。当前优先采用可恢复的服务器权威架构，避免额外依赖 TURN。参考：[Socket.IO 恢复](https://socket.io/docs/v4/connection-state-recovery/)、[客户端连接选项](https://socket.io/docs/v4/client-options/)、[MDN 页面可见性](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)、[WebRTC TURN](https://webrtc.org/getting-started/turn-server)。

AI 只收到 `engine.view(state, aiPlayer)`，不读取隐藏舰位、雷图、盖牌、数独答案或尚未播放的音符。搜索在 Web Worker 中运行，不占据主线程。最高档“大师”代表本项目的最高策略强度，未声称达到职业棋力或必胜；运气游戏存在无法确定的信息。

单人进度、已观察的 AI 记忆保存在同一浏览器，可暂停、重载后继续。更换浏览器、清理站点数据不会共享这些本地存档。今日种子由本地日期与游戏确定。正式服务端题库与离线演示题库分别维护。

## 部署和边界

新版默认端口 4390。升级时保留旧 4387 服务及旧隧道，旧状态备份为 `runtime/legacy-state-before-v2.json`，避免强行结束旧房间。新建房间使用新版公网地址。运行时、缓存、数据库、日志均在 D 盘。

GitHub Pages 仅托管页面；本机休眠、关机或公网入口故障仍会使远程服务不可用。当前临时隧道不具备固定地址和运营级可用性保证。HTTP 兼容通道与实时通道共用本机和公网入口，不能抵御整个入口失效。长期固定公网入口需自有命名隧道 / 域名或常驻云主机，不能通过浏览器代码消除这一依赖。

验收使用独立浏览器上下文和手机视口；实际异地手机、蜂窝网络、系统强制杀后台尚需真实设备验证。测试控制器基准用于发现规则或 AI 卡死，不等同人类对战胜率。
