# DUO PLAY · 双人游乐场

20 款小游戏，一个双人房间。支持手机 / 电脑、六位房间码、链接邀请、双方准备、在线对战、结算、重连、3/5 场随机巡回赛、音效开关与本机战绩。

在线页面：**https://yjj0339.github.io/duo-play/**

视觉系统「云间糖屋」：云白底色、蜜桃粉（玩家一）× 薄荷绿（玩家二）双人配色、淡紫点缀，全站浅色毛玻璃。

## 两个人怎么玩

1. 房主在自己的电脑上双击 `启动双人游乐场.cmd`，等待本机服务和公网入口就绪。
2. 打开上述在线页面，输入昵称、选择游戏、创建房间。
3. 复制房间里的邀请链接发给搭档，或告诉对方六位房间码；邀请链接自动携带服务器地址。
4. 两人都点击准备，经过 3 秒同步倒计时后开局。每款游戏内可展开玩法说明；结算后可再来一局或返回房间换游戏。
5. 房主选择 3/5 场巡回赛后，每场结算点击下一场，系统随机选择下一款，双方重新准备。

第一次打开时浏览器可能需要几秒连接服务器。遇到服务器离线，打开右上角连接设置，重新获取公开地址，或粘贴房主提供的 HTTPS 地址。

本机 `http://127.0.0.1:4387` 也可直接打开游戏。大厅提供明确标注的"同设备轮流试玩"：切换操控玩家查看双方玩法，它不包含 AI 对手，也不是两套同时响应的键盘。

## 本机与公网入口

GitHub Pages 只托管前端。真实房间、随机数、规则判定、隐藏信息、计时、碰撞和胜负在本机 Node.js 服务器计算。**客户端只发送操作，从不上传分数、生命或胜者。**

- **远程对战要求房主电脑开机、联网，且 Node.js 服务与隧道进程保持运行。** 关闭电脑或停止服务后，网页仍可打开，在线对战不可用。
- 临时 Cloudflare Tunnel 没有固定域名或持续可用性保证，每次新建隧道地址可能变化。长期使用可将同一后端连接到自有固定域名 / 命名隧道。
- 启动工具会尝试把新的公开入口写入仓库的 `runtime-endpoint.json`。页面从该文件获取当前地址，避免每次隧道重启都重新构建前端。若本机 GitHub CLI 未登录或没有权限，仍可复制启动工具输出的带 `server` 参数链接发给搭档，不影响本地服务启动。

浏览器会自动重连；刷新当前标签页也会保留这个标签页的身份。对局中断线超过 60 秒判负。服务器重启会清空进行中的内存房间，**不恢复重启前正在进行的对局**。SQLite 只保存已经结束的比赛。

## D 盘运行

本机项目：`D:/codexAI/duo-play`。Node 使用 `D:/codexAI/.toolchains/emsdk/node/24.19.0_64bit/node.exe`，所有项目依赖、临时文件、数据库、下载、浏览器资料和日志都保留在 D:。

```powershell
& 'D:\codexAI\.toolchains\powershell\pwsh.exe' -NoProfile -File 'D:\codexAI\duo-play\scripts\start.ps1'
```

停止：双击 `停止双人游乐场.cmd`。脚本仅停止记录在本项目状态文件内、且命令行匹配本项目的 Node / 隧道进程。

`runtime/` 包含私有运行资料，不纳入 Git：

- `runtime/bin/cloudflared.exe`：公网隧道执行程序
- `runtime/logs/`：服务与隧道日志
- `runtime/data/duo-play.sqlite`：已结束的对战记录
- `runtime/state.json`：本项目启动的进程与当前地址
- `runtime/temp/`：临时文件

## 开发与验证

安装依赖前设置 D: Node PATH、TEMP、TMP 和 npm 缓存，然后执行 `npm ci`。

| 命令 | 作用 |
|------|------|
| `npm test` | 135 项规则 / 房间协议 / 真实 Socket.IO 网络测试 |
| `npm run build` | 生成 `dist/` |
| `node qa/online-smoke.mjs` | 20 款游戏的双客户端真实联机开局到结算 |
| `node qa/engine-playthrough.mjs` | 只读玩家视图的测试控制器，模拟 20 款从开局到结算 |
| `node qa/visual-audit.cjs` | 20 款 × 3 视口截图，并自动检测溢出 / 深色回退 / 触控尺寸 |
| `node qa/inspect-ui.mjs` | 用 D 盘 Playwright 检查 320/390px 渲染与双浏览器联机 |
| `node qa/verify-online.mjs` | 检查线上发布后的实际双浏览器操作 |

浏览器验证依赖本机 D 盘测试工具（`D:/codexAI/.runtime/browser-tools`、`D:/codexAI/.runtime/browsers`）；Actions 工作流只运行纯 Node 规则与网络测试。

验证结果见 `docs/验收记录.md`。**真实异地手机 / 蜂窝网络验证需要实际第二设备，不能由同一电脑的两个浏览器上下文替代。**

## 源码结构

```
client/          前端外壳：大厅、联机、结算、试玩、设计系统、图形库
shared/          20 款游戏的目录（名称、规则、分类、配色）与引擎聚合
games/           三个游戏组：*-engines.js 纯规则 · *-views.js 渲染器 · *.css 组样式
server/          房间与身份服务、HTTP + Socket.IO、SQLite 落库
tests/           规则 / 房间协议 / 网络测试
scripts/         start.ps1 · stop.ps1 · publish.ps1 · 各类验收脚本
docs/            制作提示词、视觉规范、验收记录、引擎契约
```

完整制作提示词见 `docs/制作提示词.md`，视觉规范见 `docs/VISUAL-SPEC.md`，引擎接口见 `docs/CONTRACT.md`。

## 发布

前端由 GitHub Actions 自动构建并发布到 GitHub Pages（`.github/workflows/pages.yml`），也可手动执行 `scripts/publish.ps1`（测试 → 构建 → 推送 `gh-pages` 分支）。页面只托管前端，联机服务始终运行在本机。

公开仓库不包含访问令牌、隧道凭据、数据库或用户浏览器资料。
