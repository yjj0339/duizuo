# DUO PLAY · 项目说明

给后续维护者看的结构说明：它是什么、怎么跑、数据怎么走、怎么加一款新游戏。

## 1. 它是什么

一个**两人在线对战小游戏合集**。20 款玩法互不相同的游戏，共用一个双人房间系统：

```
大厅 → 选游戏 → 建房/加入 → 双方准备 → 3 秒同步倒计时 → 对战 → 结算 → 再来一局 / 换游戏
```

同一个房间还能开 **3 场 / 5 场巡回赛**：每场结束随机换一款游戏，累计比分决出总冠军。

## 2. 架构：谁说了算

核心原则只有一条：**服务器说了算，客户端只发按键。**

```
浏览器 (client/)                      本机 Node 服务 (server/)
┌──────────────────────┐              ┌──────────────────────────────┐
│ 大厅 / 房间 / HUD     │  ──Socket.IO─▶│ 房间 Rooms：身份、房间码、   │
│ 游戏渲染器 (*-views)  │              │ 准备、倒计时、巡回赛、限流    │
│ 只提交操作 action     │              │ 在场检测、暂离保护、冻结时钟  │
│ 只显示服务器给的 view │  ◀──snapshot──│ 游戏引擎 (*-engines)         │
│                       │              │ 规则判定、随机、计时、隐藏信息 │
│ 连接层 connection.js  │  ──HTTPS长轮询─▶ 得分、胜负、超时              │
│ 断线自动切换备用通道   │              │ SQLite：已结束对局 + 进行中   │
└──────────────────────┘              │ 房间的私有检查点              │
                                       └──────────────────────────────┘
```

| 关注点 | 归属 |
| --- | --- |
| 落子是否合法、子弹是否命中、谁赢了 | `games/*-engines.js`（服务端） |
| 敌舰位置、答案选项、唯一解、雷区 | 只在服务端状态里，`view()` 按玩家过滤后才下发 |
| 分数、生命、剩余时间、行动方 | 服务端计算后随 snapshot 下发 |
| 动画、插值、粒子、音效、输入法 | 客户端（纯表现） |
| 断线、暂离、时钟冻结、恢复 | 服务端 `rooms.js` 持有权威时间轴 |

任何客户端提交的 `score` / `winner` / `time` 都会被丢弃——`server/rooms.js` 的 `action` 分支只接受 `{type, ...}` 形状的操作对象。

### 两条连接通道，一套权威规则

`client/connection.js` 封装了连接生命周期：

1. 默认走 **Socket.IO**（先 HTTP 轮询再升级 WebSocket）。
2. 6.5 秒连不上，或中途断开 4.5 秒，自动切到 **HTTPS 长轮询 API**（`server/http-channel.js`）。
3. 两条通道都走同一个 `rooms.handle()`，共享房间、序号、令牌与规则，可以在同一局中随时切换。
4. 右上角连接设置可主动选择"HTTPS 兼容"通道。
5. 同一个房间在另一个标签页恢复时，旧连接会收到 `session-replaced` 并被明确提示，不会出现两个"你"。

### 断线保护与时钟冻结

- 断线、切后台、关闭页面都会把该玩家标记为"暂离"，**对局时钟立即冻结**（`room.pausedAt`），棋盘、球、炸弹不会在对方不在时继续跑。
- 保护期 **3 分钟**。双方都回来后，经过 2 秒倒计时继续，冻结的时长通过 `timeShift` 补偿回游戏时间轴。
- `snapshot()` 会把所有 `*At` / `*Until` 时间字段按冻结量平移，所以客户端倒计时和服务端完全一致。
- 超过保护期未返回才按缺席结算。

### 服务器重启恢复

服务端每 2 秒及关键房间事件把进行中房间写进 SQLite 的 `active_state` 表（私有检查点，含令牌与序号）。重启后可以恢复原房间、棋盘与双方身份，并重新给予返回保护期。**意外断电最多丢失最近约 2 秒的过程。** 检查点只留在 D 盘，不进入 Git。

## 4. 网络协议

所有事件都是 Socket.IO 的 **ack 模式**（`emit(event, payload, ack)`），`ack` 返回 `{ok, message?, code?, ...}`。

| 事件 | 方向 | 载荷 | 说明 |
| --- | --- | --- | --- |
| `create` | → | `{name, gameId}` | 建房，返回 `{code, player, token, nextSeq}` |
| `join` | → | `{code, name}` | 加入六位房间码房间；满员返回 `FULL` |
| `resume` | → | `{token}` | 用会话令牌恢复身份（刷新页面、断线重连） |
| `select` | → | `{gameId, series}` | 房主换游戏 / 设巡回赛场次 |
| `ready` | → | `{ready}` | 准备开关；双方就绪触发开局 |
| `rematch` | → | — | 再来一局 / 巡回赛进入下一场 |
| `action` | → | `{seq, action}` | 游戏操作；`seq` 单调递增，重复即被拒 |
| `react` | → | `{emoji}` | 表情互动 |
| `leave` | → | — | 离开房间 |
| `snapshot` | ← | 完整房间 + 本玩家视角的 `game` | 服务端 30Hz 推送（每 2 次 tick 推一次） |
| `ping-check` | ↔ | — | 客户端 6 秒一次测延迟 |

**身份**：`create` / `join` 返回一个 24 字节随机 `token`，客户端存在 `sessionStorage`。重连时用 `resume` 换回同一个 `player` 槽位，服务端会把旧连接的映射清掉，避免一房三连。

**限流**：每连接每秒最多 150 次事件；每个玩家每秒最多 120 次 `action`；`seq` 必须严格递增。

**断线**：连接断开只标记 `connected=false` 并记时间戳，**60 秒内可以重连回原座位**；超过 60 秒本局判负（双方同时掉线判和）。

## 5. 引擎接口

见 `docs/CONTRACT.md`。要点：

```js
create(seed, now)            → state
action(state, player, act, now) → boolean   // 只在合法时改 state
tick(state, dt, now)         → void          // 可选，30Hz
view(state, player)          → plain JSON    // 按玩家过滤，隐藏信息绝不能外泄
```

- `player` 只能是 `0` 或 `1`。
- `state` 必须可 JSON 序列化，且始终含 `status` / `winner` / `scores` / `message`；`winner=-1` 表示和棋。
- 引擎里**不能用真定时器**，所有时间由 `now` 注入，方便测试。
- 随机用状态内 PRNG，种子不外泄。
- `view()` 返回的对象必须是副本，不能把内部数组引用直接抛出去。

## 6. 加一款新游戏

1. 在 `shared/catalog.js` 加一条目录项（id、名称、分类、规则、配色、时长、操作说明）。
2. 在对应组的 `games/*-engines.js` 里实现 `create / action / tick / view`，并在 `games/*-views.js` 里实现渲染器。
3. 在 `games/*.css` 里加命名空间样式，只用 `docs/VISUAL-SPEC.md` 里的设计令牌。
4. 在 `tests/<group>.test.js` 补规则测试：**先看它失败，再让它通过**。
5. 更新 `qa/online-smoke.mjs` 与 `qa/visual-audit.cjs` 的游戏清单。

引擎和渲染器通过 `shared/engines.js` 自动聚合，前端通过 `client/main.js` 的 `renderers` 映射自动挂载——不需要改外壳。

## 7. 隐藏信息是怎么保证的

- 所有游戏状态存在服务端内存里，`view(state, player)` 是唯一的出口。
- 隐藏海战：敌方舰船坐标只在被命中后才进入玩家视图。
- 翻牌记忆：未翻开的牌面在服务端是"未揭示"，不进入视图。
- 扫雷：未打开格子的雷数不进入视图。
- 知识擂台：每题答案在两人都提交前不进入视图。
- 数独：唯一解不进入视图；`view` 只回传玩家已填内容与服务端校验结果。

`qa/online-smoke.mjs` 会扫描每份 snapshot 是否泄漏私有字段（`_rng` / `_solution` / `_questions` / `_sequence` / `mineMap` / `enemyFleet` / `serverSecret`），`tests/` 里也有对应的断言。

## 8. 本机运行与公网

- 服务端在本机 `D:/codexAI/duo-play` 运行，监听 `http://127.0.0.1:4387`。
- 远程对战通过 Cloudflare Tunnel 暴露 HTTPS/WSS 入口。**这要求房主电脑开机、联网、服务与隧道都在运行。**
- 临时隧道没有固定域名，长期使用请接命名隧道或独立云主机。
- GitHub Pages 只托管前端（`dist/`），页面从主分支的 `runtime-endpoint.json` 读取当前对战服务地址。

## 9. 已知边界

- 后端重启会清空进行中的房间，**不恢复重启前的实时对局**；SQLite 只保留已结束对局。
- 同一个标签页刷新会保留身份；换浏览器或清缓存会失去座位。
- 反应力与打字这类游戏对网络延迟敏感，界面会给出提示，但不保证公平性。
- 浏览器验证是在同一台电脑的两个浏览器上下文里完成的，**不等于真实异地手机 / 蜂窝网络测试**。
